# 后端审查与验证记录

适用版本：数据库版本 2，16 张表、96 个字段、15 项 submit 业务绑定。审查对象为 app 中的认证、RBAC、事件派发、业务服务、数据库与路由，以及 tests/test_system.py、test_independent_review.py、test_business_v2.py、test_migration.py。字段与事件说明以当前实际实现为准。

## 1. 结论与证据范围

当前代码阅读与已归档回归中，未发现可复现的重大权限绕过、跨用户越权修改、业务半次提交或同一实物重复借出问题。最终后端执行结果为 **85 passed in 69.39s**，JUnit 中 85 项、0 failure/error。全量证据为 evidence/pytest-results.xml 与 evidence/pytest.txt；evidence/pytest-persistence.xml 若保留，是同一全量中的持久化子集，不重复计数。

本结论不等同生产安全审计、长时间负载测试或所有状态/输入组合的穷举。版本 2 的最终 evidence/browser/result.json 为 passed:true，真实Edge浏览器34步全部通过，包含主数据、独立审批、双检查借还、维护启停和15事件审计；无JavaScript异常或非预期HTTP错误。具体自动化、代码审查与尚未专项验证项目列于 acceptance.md。

## 2. 已修复的输入处理问题

格式损坏的 Origin（例如 http://[）曾使 urlsplit 抛出 ValueError，得到内部错误500。修复后 same_origin 只捕获URL解析错误并转换为403/CSRF_FAILED，保留精确同源比较；受控事件记denied，业务记录不变。回归 test_malformed_origin_is_rejected_as_csrf_instead_of_internal_error 在最终85项中通过。该问题没有允许越权或导致业务写入。

## 4. 数据迁移与历史真实性

迁移回归 test_v1_migration_preserves_all_existing_data_and_backup 证明：旧12表库升级为16表，原主键、7张RBAC表、会话和审计保持，先生成完整旧库备份，外键检查无违规。旧已借出/已归还预约的工作流规范为approved，展示再由借还记录推导。

原来没有的创建人、审批时间或借还经办人保持NULL；旧已归还记录的condition_note迁入return_condition，无法恢复的checkout_condition留空，验收标记unknown。旧维护标记的时间注明为迁移登记时间，不能冒充原始开始时间。再次初始化不重复迁移或重灌现有数据；另一个未被指定的数据库文件不会被测试触碰。

设备新增创建人/创建时间/更新时间、预约updated_at由新操作在服务端填写；迁移缺项不补造。实验室负责人仅为业务关系，没有隐含角色授予；分类/实验室停用后设备派生不可用，不删除原历史。

## 5. 可复现命令与边界

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

测试使用隔离数据库；桌面沙盒若默认临时路径不可写，可将 --basetemp 指向工作区内专用测试目录。应用对象重建持久化测试已通过，但不声称实际操作系统进程重启已专项验证。动态菜单撤权UI、专项XSS攻击字符串、--reset破坏性重建等未经专项执行的项目，保持代码审查或未专项验证状态。

RBAC定位为平面多角色并集叠加业务记录约束；没有角色继承、自选会话激活或正式SSD/DSD。禁止自审不能替代互斥角色策略；即时撤权也不能作为DSD实现证据。
