## 1. 审查结论

目前未发现可复现的重大授权绕过、跨用户越权修改、业务半次提交或实体设备重复借出问题。发现一处可以稳定复现的错误输入处理问题：格式损坏的 Origin 头触发 URL 解析异常并返回 500。实现责任人已将其改为明确的 CSRF 403 拒绝，审查者已复核代码，对应回归在项目最终测试中通过。此问题不允许攻击者绕过权限，也没有造成预约状态修改。

结论仅适用于本轮代码阅读和真实执行的指定测试文件；不代表完成生产安全审计、长时间压力测试、所有 HTTP 输入穷举或全部人工界面验收。

## 2. 已复现问题及修复建议

### F01：损坏 Origin 应返回 CSRF 拒绝，实际进入内部错误

复现步骤：正常登录取得 Cookie 与 CSRF 令牌，再向 `/api/events` 提交 `reservation.cancel` 和合法目标，附请求头 `Origin: http://[`。`auth.same_origin` 调用 `urlsplit(origin)` 抛出 `ValueError: Invalid IPv6 URL`，统一错误处理器返回 500 / INTERNAL_ERROR。

预期：来源无法解析时以 403 / CSRF_FAILED 拒绝，事件审计记为 denied，业务记录保持原状。建议仅在 `same_origin` 中捕获 URL 解析的 ValueError 并转换为领域错误；不要放宽来源比较，也不要忽略这个头。

对应回归：`test_malformed_origin_is_rejected_as_csrf_instead_of_internal_error`。修复前单独真实执行得到 `1 failed, 1 passed in 11.01s`，失败断言为 `500 == 403`；另一个通过用例是故意注入成功审计失败的事务验证。修复后的 `same_origin` 已捕获 ValueError 并转换为 CSRF_FAILED，保留原有精确同源比较。F01 的最终复核归档见第 5 节。

## 3. 新增独立用例覆盖

| 关注点 | 实际检查方式 |
| --- | --- |
| 动态 RBAC | 同一 Cookie 会话撤销审批权限后立即 403；分配和移除教师角色后能力即时改变 |
| 数据库持久化 | 保存撤权后重建 create_app 连接同一数据库，复用持久化会话，检查种子不会覆盖授权；这是应用对象重建测试，不等于真实 OS 进程重启 |
| 所有权与职责约束 | 学生直接取消他人记录拒绝；本人取消允许；manage 可取消他人；教师与多角色账号都不可自审 |
| 固定事件白名单 | 伪造 envelope / payload 的 object、operation、handler 不改变绑定；未知 source_id 拒绝；伪造申请人和审批状态无效 |
| 页面/菜单/按钮区别 | 撤菜单许可不自动撤业务许可；撤页面许可阻止列表接口，保留的独立业务许可仍可在身份结果中核实 |
| 事务与失败审计 | 处理器写到一半抛领域错误，业务更新回滚，失败审计保留；成功审计写入故障也回滚业务，返回通用 JSON 500 且不泄漏内部细节 |
| 真实多连接竞争 | 两客户端同时占同一区间只有一笔成功；不重叠预约同时办理同台设备借出仍只有一笔成功；并发归还只有一笔成功 |
| 维护状态 | 维护设备不能申请；有效预约阻止切维护；模拟外部状态变化后借出仍重新校验维护状态 |
| 日期边界 | 过去、相等/逆序结束、秒精度、时区串、无效日期拒绝；半开区间首尾衔接允许；结束前/结束时/结束后借出边界 |
| 会话与 CSRF | 缺令牌、错令牌、跨源拒绝；注销后旧 Cookie 不可复用；重新登录轮换令牌；12 小时到期边界拒绝 |
| 授权保存与管理员保护 | 非法/重复许可数组不部分替换；4 项管理员管理入口许可逐项受保护；无效角色数组拒绝；最后管理员不可移除，有第二管理员后可交接 |

故障注入用例是对异常路径的主动验证，不应写成系统在正常操作时发生过真实审计故障。直接更改维护状态仅用于构造防御性验证前置条件，不代表页面允许绕过预约维护保护。

## 4. 验证过程与材料一致性

默认 pytest 临时目录位于 Windows 桌面沙盒的 AC/Temp，本环境无法创建编号目录，首次执行在 fixture 阶段报环境错误。随后使用工作区内专用 `--basetemp`，不改生产路径，不申请额外权限。

首轮完整独立用例执行结果为 `1 failed, 28 passed in 73.28s`。其中失败原因是用例仍预期故障向测试客户端抛出异常，而实现已增加统一 JSON 500 处理器；该用例已改为验证实际公开响应、回滚与审计，之后单独通过。此项属于测试与新增错误处理接口同步，不属于业务事务缺陷。

代码阅读中识别并协调了以下材料/实现一致性问题：

1. 审计员种子权限包含所有受支持的 `:view`（也包括 rbac:view），并显式拥有 reservation:export；该角色不具备业务变更许可。design.md 的矩阵已据此拆分查看/管理、manage/export。
2. 最终借出检查使用 `end_at <= now()` 作为过期条件，与半开区间相同；契约和设计已统一为“当前时间必须严格早于结束时间”。边界测试推进十天后重新登录，以免 12 小时会话先过期而把业务断言误测为 401。
3. 事件审计目标现在除了 id / reservation_id，还覆盖 role_id、user_id、equipment_id；角色授权和用户角色分配因此能够定位目标。本轮已检查固定字段和整数类型核验，具体回归结果归入项目最终证据。
4. 种子历史记录的预约创建、借出、归还时间改为符合先后顺序的相对时间；已归还样例位于过去，借出时刻为预约开始后、归还时刻为预约结束前。此为演示数据一致性修正，不冒充真实用户操作经历。

独立审查者运行指定独立测试及定向持久化测试；项目负责人统一完成全项目测试归档。界面检查数量和远程仓库状态由各自实际验证记录提供，本文不据此猜测。
